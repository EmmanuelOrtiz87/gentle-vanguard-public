Knowledge systems

Obsidian/Knowledge Base, Engram, Nexus, CodeGraph y Graphify trabajan juntos, pero cada uno tiene un rol y una autoridad distinta.

Obsidian / vault

Conocimiento curado y portable en Markdown.

knowledge-base/

No es un servicio multiusuario ni un almacén de secretos.

Engram

Memoria persistente de sesiones, decisiones y aprendizajes.

.engram-data/ + MCP

Observations, provenance, summaries y veredictos explícitos.

Nexus

SQLite WAL para métricas, tokens y estado operacional.

.runtime/gentle-vanguard.db

Autoridad de agregados, no de decisiones semánticas.

CodeGraph / Graphify

Índice de tooling incremental y grafo AST determinista para análisis.

.codegraph/ · graphify-out/

Complementarios, no fusionados.

Flujo y sincronización

Sesión → Engram ── export ──→ knowledge-base/00-inbox/ ├──────────────→ Nexus (operación) ├──────────────→ CodeGraph (.codegraph/) └──────────────→ Graphify (graphify-out/) Notas seleccionadas ── import ──→ Engram

La sync es aditiva y deduplica por hash. Previsualizá antes de escribir:

npm run kb:sync -- --mode full --dry-run
npm run kb:sync -- --mode full
npm run kb:sync -- --mode session-summary

Comandos de operación

Necesidad Comando Límite
Estado de Nexus npm run db:health estado local actual
Buscar código npm run graphify -- query "..." AST, no semántica total
Explicar nodo npm run graphify -- explain <node_id> requiere ID exacto
Actualizar grafo npm run graphify -- update . ejecutar tras editar
Health del stack npm run watchtower:health no reemplaza revisión humana

Límites honestos

  • CodeGraph se mantiene por sync incremental; Graphify usa contains/calls y tiene alcance limitado.
  • Labeling opcional consume cuota Gemini de 20 requests/día.
  • Visualizaciones grandes requieren límite de nodos.
  • La ausencia de una fuente o de un backup no se rellena automáticamente.
